# NPS · Minecraft

把 Minecraft 里的**挖掘进度**、**方块放置余量**、**当前手持物品与耐久**，实时镜像到 Windows 的 NotchPeninsula 灵动岛：

| 作品 | 目录 | 平台 | 技术栈 |
| --- | --- | --- | --- |
| **NPS · Minecraft（模组）** | `DynamicIsland-MC/` | Minecraft Java 26.1.2 | Fabric Loom 1.18.2 · Java 25 |
| **NPS · Minecraft（插件）** | `NpsDynamicIsland/` | Windows · NotchPeninsula | C# · .NET 10 · SkiaSharp 2.88 |

两者由同一条本地回环 UDP 链路驱动：**模组采集并推送，插件接收并呈现**。

---

## 一、参考视频中的核心功能

视频（`Devlog注意我的灵动岛.mp4`）演示的是屏幕顶部中央的动态岛，逐帧比对后归纳出两个功能：

| 功能 | 视频证据 | 表现 |
| --- | --- | --- |
| **挖掘进度** | 8s → 27%、16s → 46%、48s → 40%、52s → 58%、56s → 100% | 胶囊横向展开，内含圆点图标 + 圆角进度条 + 百分比 |
| **方块余量** | 68s `Scaffold`、72s → 343、76s → 316、92s → 277、96s → 252 | 展开显示方块标识与剩余数量，数秒后自动收起 |

已按你的要求剔除视频中的其余 HUD（左上角 FPS/时钟信息条、目标信息条、药水效果、服务器信息面板）。

## 二、功能对应关系

**游戏端不再绘制任何界面** —— 动态岛只呈现在 Windows 桌面上。模组只做三件事：
跟踪状态、经本地回环把状态发出去、提供一个手动唤出的按键。

| 能力 | Fabric 模组（游戏内） | NPS 插件（Windows 桌面） |
| --- | --- | --- |
| 动态岛本体 | 不绘制 HUD | `IWidget` 组件，位于灵动岛内 |
| 背景 | 无 | **不铺底色**，内容直接画在宿主自己的背景上 |
| 待机态 | 上报当前物品（`HELD`）：主手优先，主手为空取副手 | **只画一个图标**，不占文字宽度：该物品的原版纹理；两手都空时是 Minecraft 图标；**与游戏断开时整个组件隐藏** |
| 挖掘展开 | 推送进度百分比 | **环形进度条套在图标外**，右侧依次是方块名与百分比 |
| 放置展开 | 推送背包余量 | 图标 + `方块名 ×余量` |
| 滚轮换物品 | 推送当前选中物品 | 图标 + `物品名 ×数量`（单个省略 ×1） |
| 耐久 | 可损坏物品附上剩余/上限 | 物品旁画一条耐久条与 `剩余/上限`，低于两成转告警色 |
| 物品图标 | 下发纹理 PNG 的 Base64 | 解码后按物品缓存，以最近邻采样绘制原版像素纹理；拿不到时退回 Minecraft 图标 |
| 展开动画 | — | 由宿主弹簧动画完成宽度过渡；内容变化时调 `InvalidateWidgetLayout()` 请求重测，收起时同样回收宽度 |
| 手动唤出 | 按 `G` 推送当前手持物品 | 收到后展开卡片 |
| 查看详情 | 无 | 左键点击组件切换详情页（连接状态、报文统计） |
| 自动收起 | — | 放置 / 物品卡片 3.2 s 后回到待机 |
| 心跳 | 每 2 秒一条 `PING` | 8 秒收不到任何报文才判定断开 |

**数据链路**

```
Fabric 模组                                   NotchPeninsula 插件
┌───────────────────────┐                    ┌────────────────────────┐
│ MiningTracker         │                    │ IslandLinkServer       │
│ PlacementTracker      │──UDP 127.0.0.1──▶ │  :25585                │
│ SlotTracker           │   25585            │   ↓                    │
│ IslandBridge (发送)    │   单行文本协议      │ IslandSnapshot (快照)   │
└───────────────────────┘                    │ IslandWidget (宿主绘制) │
                                             └────────────────────────┘
```

**协议**（单行 UTF-8 文本，`|` 分隔）

状态报文固定八段，缺失的可选段写成空串 —— 定长分段让插件按固定下标取值，
不必写一堆「第几段存在吗」的分支，空段的代价只有一字节：

```
DI|TYPE|数值|名称|RRGGBB|图标|耐久当前|耐久上限
DI|IDLE
DI|PING
```

- **名称**由模组按客户端语言本地化后下发，插件不做翻译。
- **颜色**取自方块的 `MapColor`，非方块物品下发 `-1`。
- **图标**是客户端资源包里 16×16 纹理 PNG 的 Base64（实测 150–330 字节）。
  取不到时整段省略，插件退回 Minecraft 图标；**节流省略时**则由插件沿用同一物品的缓存位图 ——
  两种「空段」含义不同，插件按物品名区分。
- **耐久**仅对可损坏物品下发；缺失为空串，插件就不画耐久条。
- **`HELD` 与 `SLOT` 的分工**：`SLOT` 表示「刚切换了物品」，会让岛上展开卡片；
  `HELD` 只更新待机图标，不会展开。名称为空表示两手都空，插件回到 Minecraft 图标。

### 性能设计

| 端 | 约束 | 违反的后果 |
| --- | --- | --- |
| 插件 | **只有「宽度可能变化」时才递增 `Revision`** —— 挖掘进度不改变宽度，不得递增；方块名变了才要 | 宿主每秒被要求重测 20 次全部插件组件，实测就是「很卡」的主因 |
| 插件 | **连接状态翻转时也要递增 `Revision`** —— 断开会让整个组件让位，宽度归零 | 退出游戏后岛上的内容一直挂着不走（组件收不到「要重测宽度」的通知） |
| 插件 | 图标按**物品名**缓存；报文省略图标段时**沿用同名缓存**，不重新解码 | 每帧一次 PNG 解码；且挖掘期间除首条报文外图标全部丢失 |
| 插件 | `SKPaint` 按线程复用，不每帧新建 | 每帧若干个原生对象的分配与析构，成本直接摊在渲染路径上 |
| 插件 | 字形过滤按「字体面 + 原文」缓存整串结果 | 每帧一次逐字符原生字形探测 |
| 模组 | **纹理读取与 Base64 编码放在后台线程**，tick 线程只查内存缓存 | 首次遇到某物品时要打开资源包、解压 zip 条目 —— 这一步原先在渲染线程上，换物品 / 挖新方块时会卡一帧 |
| 模组 | **UDP 发送放在后台线程**，队列满则丢新报文 | `send` 是系统调用，杀软 / 防火墙检查回环时偶尔拖到毫秒级 |
| 模组 | 待机刷新只比「物品本体」，不比数量 | 放置方块时数量每块都变，而待机态只画图标 —— 原先每块都白发一条报文 |
| 模组 | 图标按物品 **3 秒节流**重发，其余报文省略图标段 | 报文体积翻数倍，且插件每秒做多次无效解码比对 |
| 模组 | 挖掘推送两道闸门：进度**变化不足 1%** 不发，间隔**不足 100 ms** 也不发 | 每 tick 一条报文，两端做二十次肉眼分辨不出的工作 |
| 模组 | 当前挖掘方块的名称与颜色按方块缓存，纹理字节按物品缓存 | 每条报文重复做本地化查找、取色与读盘 |

## 三、平台差异导致的不同实现

| 维度 | Fabric 模组 | NPS 插件 |
| --- | --- | --- |
| **职责** | 只采集与推送，**不渲染任何界面** | 只接收与呈现 |
| **语言 / 运行时** | Java 25；26.1 起 Minecraft 已不再混淆，无映射表 | C# / .NET 10；插件与宿主同进程加载 |
| **渲染管线** | 无 | SkiaSharp `SKCanvas`，浮点 + 抗锯齿 |
| **物品图标来源** | 读客户端资源包里的纹理 PNG，用 Base64 随报文下发 | 解码 PNG 后缓存，以最近邻采样绘制（像素画不做插值）；拿不到时用内嵌的 Minecraft 图标 |
| **坐标归属** | 无 | 宿主分配 `rect`；`Draw` 收到的是**岛内绝对坐标**（`Left` 常非 0），`HitTest` 收到的是**相对坐标**，内部统一按局部坐标系计算后平移一次 |
| **宽度口径** | 无 | **AutoWidth 协议**：只描述「由哪几块组成」，槽位宽 = `ceil(内容宽) + 2 × WidgetKit.AutoPadX`，向上取整与留白都由宿主完成，插件侧不再出现 `PadX*2` 这类补偿 |
| **布局约束** | 无 | 与原生内容（时间 / 硬件占用 / 媒体）共享岛体预算，空间不足时整组件本帧不显示 |
| **事件模型** | `ClientTickEvents` 每 tick 轮询公开 API | 独立接收线程 + 每帧读取不可变快照 |
| **资源生命周期** | 图标字节按物品缓存，避免每 tick 读盘 | 绘制画笔按线程复用；字体面只借不还；图标位图缓存且**不主动释放**（绘制线程可能还持引用） |
| **进度来源** | 用公开 API 复现原版破坏公式（速度 ÷ 硬度 ÷ 30 或 100） | 直接取模组推送的百分比 |

**宽度为什么交给宿主量**：AutoWidth 协议下插件只交出「图标 / 间距 / 文字实测宽」这些块，由宿主向上取整并补两侧 `AutoPadX`（1px）。口径收归一处后，插件侧不再留 `PadX*2` 的补偿，也不会出现「量 96、画 92」的偏差 —— 文字块报的就是**剔除缺字、截断加省略号之后**实际画出来的宽度。

两处刻意的取舍：`PadX` 取 5，与宿主的 1px 相加仍是迁移前的 6px 视觉留白，岛宽不变；`WidthVaries` 保持 `false`，因为本组件只在卡片到期与断连时收窄，宿主的 600 ms 变窄迟滞只会让收起慢一拍。

**挖掘进度为何这样算**：原版的破坏推进在 `MultiPlayerGameMode` 内部，读它需要 Mixin 注入私有字段，会随版本更新而失效。改用公开 API 在客户端 tick 内复现同一公式，避开了对内部结构的依赖，代价是不含服务端侧的特殊加成。

## 四、无法实现项与替代方案

| 视频中的能力 | 模组端 | 插件端 | 替代方案与原因 |
| --- | --- | --- | --- |
| 鼠标点击动态岛 | ✗ 不可实现 | ✓ 可行 | 游戏内鼠标被视角锁定，HUD 也不接收鼠标事件。**替代**：按 `G` 手动唤出当前手持物品；详请状态留待插件侧左键展开 |
| 拖动动态岛到任意位置 | ✗ 未实现 | ✗ 不可实现 | 模组侧需要一套 HUD 编辑模式（按键进入 → 拖动 → 存配置）；插件侧的组件位置由宿主统一排布，插件无权指定坐标 |
| 把文件拖入动态岛 | ✗ 无此概念 | ✓ 宿主支持 | 游戏内没有文件系统交互场景 |
| 在灵动岛上滚轮调节 | ✗ 无此概念 | ✗ 契约不支持 | 宿主不向插件转发 `WM_MOUSEWHEEL`，任何「岛上滚轮」的设计都不可实现 |
| 自定义插件配置界面 | ✗ | ✗ | 宿主**没有**「在设置窗口里给插件一块配置区」的能力（接口未接线）。配置通过宿主设置键 `Plugin.com.nps.dynamicisland.port` 调整 |
| 在游戏内显示 Windows 通知 | ✗ | — | 反向链路（插件 → 游戏）未实现：插件侧没有向游戏推消息的通道，且游戏内弹出桌面通知的意义有限 |

## 五、安装与配置

### 5.1 前置条件

| 端 | 要求 |
| --- | --- |
| Minecraft | Java 版 **26.1.2** + **Fabric Loader ≥ 0.19.3** |
| 模组依赖 | **Fabric API**（26.1.2 对应版本，如 `0.155.3+26.1.2`） |
| NotchPeninsula | 已安装并运行（插件目录 `plugins/` 与主程序同级） |

### 5.2 安装模组

1. 把 `DynamicIsland-MC/build/libs/nps-minecraft-1.0.0.jar` 复制到游戏目录的 `mods/` 文件夹。
2. 同时确认 `mods/` 中存在 Fabric API。
3. 启动游戏。按键设置中会出现「NPS · Minecraft」分类，`G` 键用于把当前手持物品唤出到岛上。

### 5.3 安装插件

1. 把 `NpsDynamicIsland/dist/NpsMinecraft/` 整个文件夹复制到 `NotchPeninsula/plugins/`（或只复制其中的 `NpsMinecraft.dll`）。
2. 在宿主「插件中心」确认插件已加载，显示为「NPS · Minecraft」。
3. 在「设置 → 显示设置 → 显示内容」中勾选它，即可上岛。

### 5.4 配置

| 项 | 默认值 | 如何修改 |
| --- | --- | --- |
| UDP 端口 | `25585` | 两端必须一致。模组侧在 `IslandBridge.PORT`，插件侧读宿主设置键 `port`（注册表 `HKCU\SOFTWARE\NotchPeninsula\Plugin.com.nps.dynamicisland.port`，字符串） |
| 模组按键 | `G` | 游戏内「选项 → 控制 → 按键绑定 → NPS · Minecraft」 |
| 心跳间隔 | 2 s（40 tick） | 模组 `DynamicIslandMod.PING_INTERVAL_TICKS` |
| 断连判定窗口 | 8 s | 插件 `IslandSnapshot.LinkTimeoutMs`。**必须大于心跳间隔**，否则岛上会反复切换连接状态 |
| 卡片保留时长 | 3.2 s | 模组 `ItemInfo` 调用侧与插件 `IslandSnapshot.PlacedHoldMs`（插件为准） |

> 端口只绑定在 `127.0.0.1`，不监听外部网卡，无需放行防火墙规则。

### 5.5 使用

1. 进入世界后，岛上只显示**当前物品的原版图标**（待机态，不占文字宽度）—— 主手没有东西时取副手；两手都空时是 **Minecraft 图标**。**与游戏断开时整块内容隐藏**，退出游戏后岛上不会残留。
2. 用工具长按挖掘方块 —— **环形进度条**从正上方顺时针推进，图标嵌在环内，右侧依次是**方块名与百分比**。
3. 手持方块右键放置 —— 展开显示该方块在背包中的剩余总数，3.2 秒后收起。
4. 滚轮切换物品 —— 展开显示名称与持有数量；若该物品可损坏，旁边还有耐久条与 `剩余/上限`。
5. 手持工具时随时能看到耐久条，剩余低于两成会转为告警色。
6. 按 `G` —— 手动把当前手持物品唤出到岛上（与滚轮切换同样的卡片）。
7. 左键点击岛上的图标 —— 展开详情页，可查看连接状态与报文统计。

> **创造模式**：方块瞬间破坏，因此不显示挖掘进度（无进度可言）；放置方块不消耗物品，
> 模组改用「按下使用键的瞬间」作为信号，余量照常显示。

## 六、从源码构建

### 6.1 模组

需要 **JDK 25**（Fabric 26.1 要求）。

```bash
cd DynamicIsland-MC
./gradlew build          # 产物：build/libs/nps-minecraft-1.0.0.jar
```

工程自带 Gradle Wrapper，其分发地址已指向国内镜像（腾讯云），无需另装 Gradle。
若本机已有 Gradle，也可直接 `gradle build`。

> **网络不可用时的离线编译**：`maven.fabricmc.net` 在国内经常只有几 KB/s 且会中途停住，
> 而 Gradle 的下载不支持续传，一次停住整条构建就失败。本机只要装过一次 26.1.2 + Fabric，
> 编译所需的一切就都在 `.minecraft` 里（客户端 jar、`fabric-loader`、Fabric API 各模块、全部第三方库），
> 可以直接用它们当 classpath：
>
> ```bash
> JAVA_HOME=/path/to/jdk-25 ./tools/build-offline.sh
> # 产物同上：build/libs/nps-minecraft-<版本>.jar
> ```
>
> 脚本默认按 `D:/Meng/Documents/PCL2/.minecraft` 找文件，可用 `MC_ROOT` / `MC_VERSION_DIR` 覆盖；
> 它不做 remap 也不生成 sources jar —— 26.1 起 Minecraft 不再混淆，编译产物与开发环境一致。

> **依赖策略**：`build.gradle` 只声明实际用到的 4 个 Fabric API 模块
> （`fabric-api-base`、`fabric-lifecycle-events-v1`、`fabric-key-mapping-api-v1`、`fabric-rendering-v1`），
> 而不是聚合包 `net.fabricmc.fabric-api:fabric-api`。聚合包会一次拉取四十余个子模块、
> 其中数个数 MB，在慢速网络下极易超时；按需引入把首次构建的下载量降到十分之一左右。
> 运行时所需的完整 Fabric API 由 `fabric.mod.json` 的 `depends` 声明，玩家自行安装。

### 6.2 插件

需要 **.NET 10 SDK**（宿主 `NotchPeninsula.csproj` 的目标框架为 `net10.0-windows10.0.19041.0`）。

```bash
cd NpsDynamicIsland
dotnet build NpsDynamicIsland.csproj -c Release
```

构建过程会自动：
1. 把产物 `NpsMinecraft.dll` 与 `plugin.json` 打包到 `dist/NpsMinecraft/`；
2. 若检测到 `D:\NotchPeninsula\plugins`，自动复制过去。

> 工程目录与工程文件名仍是 `NpsDynamicIsland`，只有**产物**按 `NPS · Minecraft` 统一命名
> （`NpsMinecraft.dll` 与 `nps-minecraft-1.0.0.jar`）—— 宿主插件目录里其余插件也都是
> `NpsXxx.dll` 这种纯 ASCII 形式，跟着这个习惯走最省事。

## 七、排查

| 现象 | 检查项 |
| --- | --- |
| 岛上只有一个图标、一直不展开 | 属正常待机状态；挖掘 / 放置 / 滚轮换物品或有事件时才展开 |
| 待机图标是 Minecraft 图标 | 主手与副手都是空的；也可能是该物品取不到纹理 |
| 岛上的内容忽然整块消失 | 8 秒内没收到任何报文即视为断开，此时按设计隐藏。检查模组是否仍在运行、两端端口是否一致 |
| 卡片收起后宽度没收回去 | 到期归位没有递增 `Revision`，组件收不到「要重测宽度」的通知 |
| **明显卡顿** | `Revision` 被在挖掘期间递增了 —— 进度不改变宽度，不该触发宿主重测 |
| **画面偶发一顿（转视角 / 移动时）** | 先看日志里有没有 `[DynamicIsland] 本模组 tick 处理耗时异常`：**有**说明是模组自己在拖帧；**没有**则卡顿另有来源（渲染、其它模组、硬件）。图标读盘与 UDP 发送已移到后台线程，正常情况下这行不该出现 |
| 图标是 Minecraft 图标而不是物品本身 | 该物品在 `assets/minecraft/textures/{item,block}/` 下没有同名 PNG，或图标超过 1100 字节上限被丢弃 |
| 文字里少了几个字符 | 当前字体画不出这些字，已按要求跳过而不渲染成方块 |
| 耐久条不出现 | 仅对「可损坏」物品显示；方块、食物等没有耐久 |
| 挖掘时不展开 | 进度只在「按住攻击键 + 准星指向有硬度的方块」期间推进。**创造模式不显示进度**；硬度为 0 的方块（草、花、火把）与空气同样不上岛 |
| 放置后不显示余量 | 仅对**方块物品**生效；需在使用键按下的瞬间准星指向方块 |
| 滚轮换物品没反应 | 只在槽位真正改变时推送；进世界后的第一次采样只上报待机图标，不弹卡片 |
| 按 `G` 没反应 | 需已进入世界 |
| 插件一直显示「未监听」 | 端口被占用，换一个端口并同步修改模组侧 |

## 八、26.1.2 的 API 变更点（开发备忘）

从 1.21.x 移植到 26.1 时实际踩到的差异，逐条已在本工程中验证：

| 项目 | 1.21.x | 26.1.2 |
| --- | --- | --- |
| 代码混淆 | Yarn / Mojang 映射二选一 | **不再混淆**，无映射表 |
| Loom 插件 id | `fabric-loom` | `net.fabricmc.fabric-loom` |
| 依赖声明 | `modImplementation` | `implementation` |
| 打包任务 | `remapJar` | `jar` |
| Java 版本 | 21 | **25** |
| 资源标识符 | `ResourceLocation` | **`Identifier`**（仍在 `net.minecraft.resources`） |
| GUI 绘制入口 | `DrawContext` | **`GuiGraphicsExtractor`**（`net.minecraft.client.gui`） |
| 按键注册 | `KeyBindingHelper.registerKeyBinding` | **`KeyMappingHelper.registerKeyMapping`**（包 `...client.keymapping.v1`） |
| 按键分类 | `String` 常量 | **`KeyMapping.Category`**，用 `Category.register(Identifier)` 注册 |
| 能否收获方块 | `canHarvestBlock(state)` | **`hasCorrectToolForDrops(state)`** |
| 物品比较 | `stack.is(item)` | `stack.getItem() == item`（`is` 已改收 `Predicate<Holder<Item>>`） |
| 读资源包文件 | `ResourceManager.getResource(id)` | **`getResourceStack(id)`** 返回 `List<Resource>`，再 `Resource.open()` |

> 另一条与构建相关的实际坑：**fabric-loader 的 jar 必须真的存在于本地缓存**。
> 声明一个本地没有的版本（如 0.19.5 而缓存只有 0.19.3）时，Gradle 在离线校验阶段不会报缺失，
> 直到编译才以「程序包 `net.fabricmc.api` 不存在」的形式暴露 —— 看起来像代码错误，实为依赖没下来。

## 九、插件生命周期与资源清理

宿主在「关闭」与「卸载」两个节点各给了一次机会，本插件两层都用上了：

| 节点 | 触发条件 | 钩子 | 本插件做的事 |
| --- | --- | --- | --- |
| **关闭** | 禁用、热重载、宿主退出 | `IDisposable.Dispose` | 关闭 UDP 监听并交还端口（含等待监听线程退出）；释放物品图标位图与 Minecraft 图标；释放绘制画笔；清空字形过滤缓存 |
| **卸载** | 用户**真正卸载**插件（禁用 / 重载 / 退出都不触发） | `IPluginHost.RegisterUninstallAction` | 上面全部再兜底执行一次（幂等）；删除本插件留在宿主设置里的注册表值 |

为什么两层都要：`Dispose` 只能处理**进程内**的资源，而插件写在注册表、磁盘上的东西宿主看不见；
卸载钩子恰好是「实例还活着、文件还没删」的时机，能在里面正常调用自己的资源，是最后一次机会。

三点实现约束：

- **不登记插件目录**。`RegisterUninstallDirectory` 会把目录标为「卸载时可一并删除」。
  本插件是宿主 `plugins/` 里的单个 dll，登记它会把整个插件目录纳入删除范围，误删其他插件。
- **设置键只删本插件前缀**。宿主把所有插件的设置存在同一个键
  （`HKCU\SOFTWARE\NotchPeninsula`）下，键名形如 `Plugin.<插件 id>.<项>`。
  清理时只匹配 `Plugin.com.nps.dynamicisland.`，其余一律不动。
- **清理失败不挡卸载**。卸载钩子里任何异常都会被吞掉并记日志 —— 宿主本身也是这么处理的，
  清理失败不应该让「卸载」变成既不成功也不报错。

> 宿主版本较旧、接口里没有 `RegisterUninstallAction` 时，`Initialize` 里的注册会以
> `MissingMethodException` 失败并被吞掉，插件功能不受影响，只是少了卸载时的注册表清理。
